1. What this app does

The PMC8 Dashboard talks to your PMC‑Eight mount controller so you can:

  • Put the mount on your home WiFi so it no longer makes its own network — and read back the address it was given.
  • Read and change the mount's configuration (the settings stored inside the controller).
  • Send individual commands and watch the replies, for testing.
  • Update the controller firmware using the built‑in uploader.

You connect to the mount one of two ways: over a USB serial cable, or over your local network (WiFi). Each task below tells you which one it needs.

The one rule to remember Anything that sets up the WiFi module, or uploads firmware, must be done over a USB serial connection — not over WiFi. (The app sends those commands to the Propeller chip inside the mount, which then relays them to the WiFi module. That only works over the cable.)

2. Installing & starting the app

The dashboard needs Python 3.10 or newer plus two add‑on packages, PyQt6 (the windows and buttons) and pyserial (the serial port). The steps below install everything.

Windows

The easy way: double‑click run_dashboard_windows.bat in the dashboard folder. It finds Python and starts the app for you. No Administrator rights are needed.

To do it by hand, open a Command Prompt and run:

py -m pip install PyQt6 pyserial
cd path\to\PMC8_Dashboard_Windows
py PMC8_Dashboard.py
"Python is not recognized" Install Python 3.10+ from python.org and tick Add python.exe to PATH during installation. Close the Command Prompt, open a new one, and try again. The launcher looks for py, then python, then python3.

macOS

  1. Extract PMC8_Dashboard_macOS.zip and open the extracted PMC8_Dashboard_macOS folder.
  2. First launch — run setup through Terminal (recommended). macOS normally blocks a freshly downloaded script on a plain double‑click, so run it through the sh program the first time, which avoids that:
    1. Open Terminal (press ⌘‑Space, type Terminal, press Return).
    2. Type sh followed by a space — but don't press Return yet.
    3. Drag the setup_macos.command file from Finder into the Terminal window (this fills in its location for you). The line should read sh /…/setup_macos.command.
    4. Press Return.
    Setup clears macOS's download protection ("quarantine") on the whole folder, sets permissions, installs the Python packages, and starts the app.

After that first successful setup, just double‑click run_PMC8-Dashboard.command any time you want to launch the dashboard — the download protection is already cleared, so it opens normally.

Why not just double-click the first time? You can try double‑clicking setup_macos.command, but on a fresh download macOS usually blocks it — you might see "insufficient privileges," "unidentified developer," or "Apple could not verify…." Running chmod does not fix this (it's a separate security tag called quarantine). The Terminal sh method above sidesteps it — that's why it's the recommended first step.
macOS may block the firmware helper once The first time you upload firmware, macOS may block the bundled p1load helper. Go to System Settings → Privacy & Security, find the blocked p1load message, click Allow Anyway, then run the upload again and approve the popup. This is a one‑time approval.

Linux / running from source

python3 -m pip install PyQt6 pyserial
cd /path/to/p1loader
python3 PMC8_Dashboard.py
Startup check Each time it starts, the dashboard quietly confirms that its required files (the uploader, the upload dialog, and this manual) are present and readable before the window opens. If something is missing it tells you which file, which usually means the download wasn't fully extracted — extract the ZIP again.

3. Quick Start — your first connection

This gets you connected and confirms everything works. You'll need a USB cable between your computer and the PMC‑Eight.

  1. Plug the PMC‑Eight into your computer with the USB cable and power on the mount.
  2. Start the dashboard (see section 2).
  3. At the top, set Connection Mode to Serial.
  4. Open the Serial Port list and pick the mount's port. On Windows it looks like COM5; on macOS/Linux like /dev/tty.usbserial-XXXX. If you're not sure which one, see the Troubleshooting tip below.
  5. Click Connect. The button turns green when the connection is open.
  6. Go to the Configuration tab and click Get Configuration. If the fields fill in with values, you're talking to the mount — you're all set.
That's it Once Get Configuration returns values, every task in this manual will work. If it didn't, jump to Troubleshooting.

4. Connecting to your mount

ControlWhat it's for
Connection ModeChoose Serial (USB cable) or WiFi (network). Use Serial for WiFi setup and firmware uploads; WiFi is for sending configuration commands once the mount is already on your network.
Serial PortThe mount's COM port (Windows) or tty device (macOS/Linux). If your port isn't listed, plug the cable in first, then reopen the app or the list.
WiFi Address / PortThe mount's IP address and command port, used in WiFi mode. You can discover the address with Get WiFi Address on the Network tab.
ConnectOpens the connection. Turns green when connected. Click again to disconnect.

5. Common tasks, step by step

5.1 Put my mount on my home WiFi

Connection needed: Serial (USB). Tab: Network.

  1. Connect over Serial (see Quick Start).
  2. Open the Network tab.
  3. Set WiFi module to match the module inside your mount: ESP32, ESP8266, or RN131. If you're unsure, ask your supplier or check the mount documentation — choosing the wrong one is the most common reason setup fails.
  4. Type your home network's SSID (network name) and Password. These are remembered for next time (see the note below).
  5. Click Configure for Home Network.
  6. Watch the log at the bottom. It reports each step, and on success shows the Assigned IP — the address your router gave the mount. Write this down; you'll use it to connect over WiFi later.
Your WiFi details are saved The SSID, password, and module choice are stored in a file named pmc8_network_credentials.json in the folder you started the app from. The Network tab fills them in automatically next time. Delete that file if you want to clear saved credentials.
Joining can take several seconds After "Joining home network…" appears, give it time — connecting to a router and getting an address isn't instant. The log will say Joined home network when it sees the address. If it warns it didn't see an address, see Troubleshooting.

5.2 Find my mount's WiFi address

Connection needed: Serial (USB). Tab: Network.

Use this any time you need the mount's current network address — it only reads the address, it doesn't change any settings.

  1. Connect over Serial.
  2. On the Network tab, set WiFi module to your module type.
  3. Click Get WiFi Address.
  4. The current address appears in the Assigned IP box and in the log.
Behind the scenes Different modules answer differently, so the app picks the right question for you: ESP32 uses AT+CIPSTA?, ESP8266 uses AT+CIFSR, and RN131 uses get ip a. You don't need to type any of these.

5.3 Reset the WiFi back to factory default

Connection needed: Serial (USB). Tab: Network.

This returns the mount to its own built‑in access‑point network — useful if it can't reach your home network or you're starting over.

  • RN131 modules: select RN131, then click Restore to Default. The mount is rewritten to its access‑point defaults (address 192.168.47.1, network name and password PMC-Eight). This takes a little while — let it finish.
  • ESP32 / ESP8266 modules: there's nothing to restore here. These modules return to default on the next mount reboot — use Boot PMC8 on the Configuration tab, or power‑cycle the mount. The Restore to Default button is disabled for these on purpose, and the tab explains this.

5.4 Read or change configuration

Connection needed: Serial or WiFi. Tab: Configuration.

  1. Click Get Configuration to read the current settings into the editable fields.
  2. Edit the fields you want to change.
  3. Click Save Configuration to send the new values to the mount.
  4. If prompted or needed after changes, click Boot PMC8 to restart the controller so the settings take effect.
Read before you write Always Get Configuration first so the fields reflect what's actually on the mount. Saving from blank or stale fields can write values you didn't intend.

5.5 Update the firmware

Connection needed: Serial (USB). Tab: Firmware / upload dialog.

  1. Connect over Serial — firmware upload does not work over WiFi.
  2. Open the firmware upload dialog and choose the firmware file.
  3. Start the upload and let it run to completion without unplugging or powering off.
The reset lines toggle — that's normal During upload the app deliberately toggles the serial reset lines (DTR/RTS) as part of programming the Propeller chip. For ordinary configuration connections it keeps those lines low instead, so it doesn't reset the mount unexpectedly.

6. Screen-by-screen reference

Network tab

  • Requires a serial connection to the mount.
  • WiFi module — ESP32, ESP8266, or RN131. Must match your hardware.
  • Configure for Home Network — sends the right sequence for your module to join the SSID you entered.
  • Get WiFi Address — reads the current address without changing anything.
  • Restore to Default — RN131 only; rewrites the module to PMC‑Eight access‑point defaults.
  • Assigned IP — shows the address found by Configure or Get WiFi Address.
  • Log — a timestamped record of every step and reply. This is your first stop when something doesn't work.

Configuration tab

  • Get Configuration — reads the controller's settings into editable fields.
  • Save Configuration — sends the displayed values back to the controller.
  • Boot PMC8 — restarts the controller after configuration or firmware operations.

Command Console

For testing and advanced use: pick a PMC‑Eight command from the list, fill in any parameter fields it needs, and click send. The reply appears in the response log.

7. Troubleshooting

SymptomWhat to try
The Configuration tab is blank after "Get Configuration" An occasional serial read drops or truncates the first reply (the log shows "Unexpected ESGi! response length"). This is harmless — the app rejects a garbled reply rather than showing wrong values. Just click Get Configuration again; the second read almost always succeeds.
My serial port isn't in the list Plug in the USB cable before opening the list, then reopen it (or restart the app). On Windows, a missing port often means the USB‑serial driver (FTDI / CP210x / CH340) isn't installed. To identify the right port, unplug the mount, note which entries disappear, plug it back in, and pick the one that returns.
Connect button won't turn green Make sure no other program (another dashboard window, a planetarium app, Arduino IDE) has the port open — only one program can use a serial port at a time. Confirm the mount is powered on and you selected the correct port.
The log shows busy p... That's the WiFi module saying "I'm still working on the last command." The dashboard already paces itself for this and reads replies patiently. If you still see it occasionally on an ESP32 (which answers more slowly than an ESP8266), simply run the action again — it's harmless. Persistent "busy" usually means the wrong WiFi module type is selected.
"Could not read WiFi address" Confirm the WiFi module selection matches your hardware, that you're on a serial connection, and that the mount has actually joined a network. Try Get WiFi Address again; the mount may have been mid‑reply the first time.
"Did not see WIFI GOT IP" after Configure Double‑check the SSID and password (the password field is case‑sensitive). Make sure the network is in range and is a 2.4 GHz network — many of these modules don't support 5 GHz. Then try again.
The mount seems "stuck" after a WiFi step The app always sends the exit command (###) to leave the mount's pass‑through mode, even if an error happened — so this is rare. If it persists, power‑cycle the mount and reconnect.
PyQt6 or pyserial "not found" at startup Install them with the command shown in the console message (pip install PyQt6 pyserial), then start the app again.

8. Glossary

TermMeaning
PMC‑EightThe Explore Scientific mount controller this app configures.
WiFi moduleThe wireless chip inside the mount — an ESP32, ESP8266, or RN131. Different modules speak slightly different command languages, which is why you select the type.
Serial / COM portThe connection over the USB cable. Shows as COMx on Windows or /dev/tty... on macOS/Linux.
SSIDThe name (Service Set Identifier) of a WiFi network.
IP addressThe mount's numeric Internet Protocol address on your network, e.g. 192.168.1.50. You need it to connect over WiFi.
Access point (AP) modeWhen the mount makes its own WiFi network instead of joining yours. "Restore to Default" returns an RN131 to this mode.
Pass‑through modeA temporary state where the mount relays your commands straight to the WiFi module. The app enters and exits it for you.
FirmwareThe software that runs inside the controller itself, which you can update from the Firmware screen.
