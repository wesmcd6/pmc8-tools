1. WHAT THIS APP DOES
==============================================================================

The PMC8 Dashboard talks to your PMC-Eight mount controller so you can:

  - Put the mount on your home WiFi so it no longer makes its own network -
    and read back the address it was given.
  - Read and change the mount's configuration (the settings stored inside the
    controller).
  - Send individual commands and watch the replies, for testing.
  - Update the controller firmware using the built-in uploader.

You connect to the mount one of two ways: over a USB serial cable, or over your
local network (WiFi). Each task below tells you which one it needs.

  >> THE ONE RULE TO REMEMBER:
     Anything that SETS UP the WiFi module, or UPLOADS firmware, must be done
     over a USB SERIAL connection - not over WiFi. (The app sends those
     commands to the Propeller chip inside the mount, which then relays them to
     the WiFi module. That only works over the cable.)

2. INSTALLING & STARTING THE APP
==============================================================================

The dashboard needs Python 3.10 or newer plus two add-on packages: PyQt6 (the
windows and buttons) and pyserial (the serial port). The steps below install
everything.

WINDOWS
-------
The easy way: double-click run_dashboard_windows.bat in the dashboard folder.
It finds Python and starts the app for you. No Administrator rights are needed.

To do it by hand, open a Command Prompt and run:

    py -m pip install PyQt6 pyserial
    cd path\to\PMC8_Dashboard_Windows
    py PMC8_Dashboard.py

  >> "Python is not recognized": Install Python 3.10+ from python.org and tick
     "Add python.exe to PATH" during installation. Close the Command Prompt,
     open a new one, and try again. The launcher looks for py, then python,
     then python3.

macOS
-----
Packaged ZIP (recommended):
  1. Extract PMC8_Dashboard_macOS.zip and open the extracted
     PMC8_Dashboard_macOS folder.
  2. FIRST LAUNCH - run setup through Terminal (recommended). macOS normally
     blocks a freshly downloaded script on a plain double-click, so run it
     through the "sh" program the first time, which avoids that:
       a. Open Terminal (press Cmd-Space, type Terminal, press Return).
       b. Type  sh  followed by a space - but do NOT press Return yet.
       c. Drag the setup_macos.command file from Finder into the Terminal
          window (this fills in its location for you). The line should read
          sh /.../setup_macos.command
       d. Press Return.
     Setup clears macOS's download protection ("quarantine") on the whole
     folder, sets permissions, installs the Python packages, and starts the app.

After that first successful setup, just double-click run_PMC8-Dashboard.command
any time you want to launch the dashboard - the download protection is already
cleared, so it opens normally.

  >> Why not just double-click the first time? You can try double-clicking
     setup_macos.command, but on a fresh download macOS usually blocks it - you
     might see "insufficient privileges", "unidentified developer", or "Apple
     could not verify...". Running chmod does NOT fix this (it's a separate
     security tag called "quarantine"). The Terminal "sh" method above
     sidesteps it - that's why it's the recommended first step.

  >> macOS may block the firmware helper once: The first time you upload
     firmware, macOS may block the bundled p1load helper. Go to System Settings
     > Privacy & Security, find the blocked p1load message, click Allow Anyway,
     then run the upload again and approve the popup. This is a one-time
     approval.

  >> If setup reports a problem:
       - "Python was not found": install Python 3.10+ from python.org, close
         Terminal, open a new window, and run setup again.
       - "A required file is missing": the ZIP was not fully extracted or files
         were moved. Delete the partial folder, extract again, and run setup
         from inside the extracted PMC8_Dashboard_macOS folder.
       - PyQt6 or pyserial fails to install: check the Mac has internet access
         and that python3 -m pip works, then run setup again.

LINUX / RASPBERRY PI (64-bit)
-----------------------------
The dashboard is pure Python and runs on Linux, including a 64-bit Raspberry Pi
(Raspberry Pi OS 64-bit / aarch64). There is NO separate compiled build to
download for the Pi - the same source runs everywhere, and firmware upload on
Linux uses the built-in Python uploader (the Mac-only p1load helper is not used
here).

Packaged ZIP (recommended):
  1. Extract PMC8_Dashboard_Linux.zip and open the extracted folder in a
     terminal.
  2. FIRST RUN - one-time setup:
       ./setup_linux.sh
     Setup installs PyQt6 + pyserial (via apt on Raspberry Pi OS, otherwise
     pip), adds you to the "dialout" group for serial-port access, and then
     launches the dashboard.
  3. After setup succeeds once, launch day-to-day with:
       ./run_dashboard_linux.sh

  >> Log out and back in before connecting (first time): setup_linux.sh adds
     you to the "dialout" group so you can open the serial port, but that group
     change only takes effect after a fresh login. If the dashboard opens but
     the serial port won't connect, log out and back in (or reboot the Pi)
     once, and it will work from then on.

  >> On Linux, connecting over serial reboots the mount - this is normal.
     Opening the serial port on Linux briefly toggles the reset line, so the
     PMC-Eight restarts every time you press Connect. The dashboard knows this:
     it shows "Mount reboots on serial connect (Linux) - waiting for it to come
     back...", waits about 20 seconds for the mount to restart, then fills in
     the configuration automatically. Just let it finish - it is not an error.
     (Windows and macOS do not reset the mount on connect.)

  >> If a .sh file isn't executable (for example the folder was copied instead
     of extracted), make them clickable first:
       chmod +x setup_linux.sh run_dashboard_linux.sh

Source / manual run (any Linux):
  On a Raspberry Pi, the easiest install uses the system packages (this avoids
  building Qt from source):

    sudo apt install python3-pyqt6 python3-serial
    cd /path/to/p1loader
    python3 PMC8_Dashboard.py

  On other Linux systems, or in a virtual environment:

    python3 -m pip install PyQt6 pyserial
    cd /path/to/p1loader
    python3 PMC8_Dashboard.py

  >> Use a 64-bit OS on the Pi: PyQt6 is available for 64-bit ARM (aarch64)
     only, so run 64-bit Raspberry Pi OS. On the Pi, prefer
     "apt install python3-pyqt6" over "pip install PyQt6" - plain pip may not
     have a matching wheel and can try to compile Qt.

  >> Serial port & permissions: On the Pi the mount usually appears as
     /dev/ttyUSB0 (FTDI/CP210x/CH340 adapters) or /dev/ttyACM0. Add your user
     to the "dialout" group once so you can open the port without root, then log
     out and back in:  sudo usermod -aG dialout $USER

  >> It's a desktop app: run it on the Pi desktop or over VNC/X, not from a
     headless SSH session with no display.

  >> Startup check: Each time it starts, the dashboard quietly confirms that
     its required files (the uploader, the upload dialog, and this manual) are
     present and readable before the window opens. If something is missing it
     tells you which file, which usually means the download wasn't fully
     extracted - extract the ZIP again.


==============================================================================
3. QUICK START - YOUR FIRST CONNECTION
==============================================================================

This gets you connected and confirms everything works. You'll need a USB cable
between your computer and the PMC-Eight.

  1. Plug the PMC-Eight into your computer with the USB cable and power on the
     mount.
  2. Start the dashboard (see section 2).
  3. At the top, set Connection Mode to Serial.
  4. Open the Serial Port list and pick the mount's port. On Windows it looks
     like COM5; on macOS/Linux like /dev/tty.usbserial-XXXX. If you're not
     sure which one, see the Troubleshooting tip in section 7.
  5. Click Connect. The button turns GREEN when the connection is open.
  6. Go to the Configuration tab and click Get Configuration. If the fields
     fill in with values, you're talking to the mount - you're all set.

  >> THAT'S IT: Once Get Configuration returns values, every task in this
     manual will work. If it didn't, jump to section 7, Troubleshooting.


==============================================================================
4. CONNECTING TO YOUR MOUNT
==============================================================================

  Connection Mode    Choose Serial (USB cable) or WiFi (network). Use Serial
                     for WiFi setup and firmware uploads; WiFi is for sending
                     configuration commands once the mount is already on your
                     network.

  Serial Port        The mount's COM port (Windows) or tty device
                     (macOS/Linux). If your port isn't listed, plug the cable
                     in first, then reopen the app or the list.

  WiFi Address/Port  The mount's IP address and command port, used in WiFi
                     mode. You can discover the address with Get WiFi Address
                     on the Network tab.

  Connect            Opens the connection. Turns GREEN when connected. Click
                     again to disconnect.


==============================================================================
5. COMMON TASKS, STEP BY STEP
==============================================================================

5.1 PUT MY MOUNT ON MY HOME WIFI
--------------------------------
Connection needed: Serial (USB).   Tab: Network.

  1. Connect over Serial (see Quick Start).
  2. Open the Network tab.
  3. Set WiFi module to match the module inside your mount: ESP32, ESP8266, or
     RN131. If you're unsure, ask your supplier or check the mount
     documentation - choosing the wrong one is the most common reason setup
     fails.
  4. Type your home network's SSID (network name) and Password. These are
     remembered for next time (see note below).
  5. Click Configure for Home Network.
  6. Watch the log at the bottom. It reports each step, and on success shows
     the Assigned IP - the address your router gave the mount. Write this down;
     you'll use it to connect over WiFi later.

  >> Your WiFi details are saved: The SSID, password, and module choice are
     stored in pmc8_network_credentials.json in the folder you started the app
     from. The Network tab fills them in automatically next time. Delete that
     file to clear saved credentials.

  >> Joining can take several seconds: After "Joining home network..." appears,
     give it time - connecting to a router and getting an address isn't
     instant. The log says "Joined home network" when it sees the address. If
     it warns it didn't see an address, see Troubleshooting.

  >> RN131 modules and modern routers: RN131 modules (common on EXOS2 mounts)
     are older 2.4 GHz radios that speak WPA and WPA2 only. They cannot join a
     network that is WPA3-only, that runs WPA2/WPA3 "transition" mode, or that
     requires Protected Management Frames (PMF / 802.11w) - all common on newer
     WiFi 6 routers. When an RN131 can see such a network but can't complete the
     login, the log shows an authentication error (AUTH-ERR) and the module
     keeps retrying. If that happens, point the mount at a 2.4 GHz WPA2 network
     - a guest or IoT SSID is ideal - rather than your main modern network. The
     ESP32 and ESP8266 modules are newer and less fussy about this.

     Passwords with spaces are fine: the app now encodes them correctly for the
     RN131. (Earlier versions truncated an RN131 password at the first space,
     which also showed up as AUTH-ERR - so if you saw that before, update and
     try again.)

5.2 FIND MY MOUNT'S WIFI ADDRESS
--------------------------------
Connection needed: Serial (USB).   Tab: Network.

Use this any time you need the mount's current network address - it only READS
the address, it doesn't change any settings.

  1. Connect over Serial.
  2. On the Network tab, set WiFi module to your module type.
  3. Click Get WiFi Address.
  4. The current address appears in the Assigned IP box and in the log.

  >> Behind the scenes: Different modules answer differently, so the app picks
     the right question for you: ESP32 uses AT+CIPSTA?, ESP8266 uses AT+CIFSR,
     and RN131 uses get ip a. You don't need to type any of these.

5.3 RESET THE WIFI BACK TO FACTORY DEFAULT
------------------------------------------
Connection needed: Serial (USB).   Tab: Network.

This returns the mount to its own built-in access-point network - useful if it
can't reach your home network or you're starting over.

  - RN131 modules: select RN131, then click Restore to Default. The mount is
    rewritten to its access-point defaults (address 192.168.47.1, network name
    and password "PMC-Eight"). This takes a little while - let it finish.

  - ESP32 / ESP8266 modules: there's nothing to restore here. These modules
    return to default on the next mount reboot - use Boot PMC8 on the
    Configuration tab, or power-cycle the mount. The Restore to Default button
    is disabled for these on purpose, and the tab explains this.

5.4 READ OR CHANGE CONFIGURATION
--------------------------------
Connection needed: Serial or WiFi.   Tab: Configuration.

  1. Click Get Configuration to read the current settings into the editable
     fields.
  2. Edit the fields you want to change.
  3. Click Save Configuration to send the new values to the mount.
  4. If prompted or needed after changes, click Boot PMC8 to restart the
     controller so the settings take effect.

  >> Read before you write: Always Get Configuration first so the fields
     reflect what's actually on the mount. Saving from blank or stale fields
     can write values you didn't intend.

5.5 UPDATE THE FIRMWARE
-----------------------
Connection needed: Serial (USB).   Tab: Firmware / upload dialog.

  1. Connect over Serial - firmware upload does not work over WiFi.
  2. Open the firmware upload dialog and choose the firmware file.
  3. Start the upload and let it run to completion without unplugging or
     powering off.

  >> The reset lines toggle - that's normal: During upload the app deliberately
     toggles the serial reset lines (DTR/RTS) as part of programming the
     Propeller chip. For ordinary configuration connections it keeps those
     lines low instead, so it doesn't reset the mount unexpectedly.

6. SCREEN-BY-SCREEN REFERENCE
==============================================================================

NETWORK TAB
  - Requires a serial connection to the mount.
  - WiFi module - ESP32, ESP8266, or RN131. Must match your hardware.
  - Configure for Home Network - sends the right sequence for your module to
    join the SSID you entered.
  - Get WiFi Address - reads the current address without changing anything.
  - Restore to Default - RN131 only; rewrites the module to PMC-Eight
    access-point defaults.
  - Assigned IP - shows the address found by Configure or Get WiFi Address.
  - Log - a timestamped record of every step and reply. This is your first
    stop when something doesn't work.

CONFIGURATION TAB
  - Get Configuration - reads the controller's settings into editable fields.
  - Save Configuration - sends the displayed values back to the controller.
  - Boot PMC8 - restarts the controller after configuration or firmware
    operations.
  - Fast Server Status - whether Fast Server (Envision) is installed on your
    WiFi module and whether it is running right now. Filled in by Get
    Configuration.
  - Boot into Fast Server - tick to have the WiFi module start in Fast Server
    mode from now on, untick to have it start normally. Click Save
    Configuration to apply the change. The box is greyed out when the option
    isn't available, and the status line says why.

  >> Fast Server needs an ESP32 or ESP8266 on current firmware: Fast Server
     mode is only available on ESP32 and ESP8266 WiFi modules, and only once
     the module has been updated to the latest firmware build. If your module
     is on an older build, the status line reads "Not installed" and the
     checkbox stays greyed out - update the module's firmware and click Get
     Configuration again.

     RN131 modules do not support Fast Server mode at all. There is no
     firmware update that adds it; the status line says it isn't available and
     the checkbox stays greyed out.

COMMAND CONSOLE
  For testing and advanced use: pick a PMC-Eight command from the list, fill in
  any parameter fields it needs, and click send. The reply appears in the
  response log.

  Below the list there's an "Or type a command:" box for anything the list
  doesn't carry - type the command exactly as you want it sent (for example
  ESGe!) and press Enter or click send. While that box has any text in it, it
  is what gets sent and the list selection is ignored, so clear it (the x at
  its right edge) when you want to go back to picking from the list.

  Two Envision (Fast Server) commands are on the list:
    ESGe!     Get Envision status. The reply is a 3-bit value: 1 = the module
              is Envision-capable, 2 = the boot flag is set, 4 = Envision is
              running right now (so 3 = capable and set to boot into it).
    ESSe<p>!  Set Envision. p = 0 stop now, 1 start now, 3 boot on, 4 boot off.
              Sending this by hand re-reads ESGe! afterwards so the Fast Server
              display stays in step. Note that 0 and 1 reboot the WiFi module,
              so the status may read Unknown for a few seconds - and over a
              WiFi connection they will drop the link you are using.

7. TROUBLESHOOTING
==============================================================================

The Configuration tab is blank after "Get Configuration"
  An occasional serial read drops or truncates the first reply (the log shows
  "Unexpected ESGi! response length"). This is harmless - the app rejects a
  garbled reply rather than showing wrong values. Just click Get Configuration
  again; the second read almost always succeeds.

My serial port isn't in the list
  Plug in the USB cable BEFORE opening the list, then reopen it (or restart the
  app). On Windows, a missing port often means the USB-serial driver (FTDI /
  CP210x / CH340) isn't installed. On Linux / Raspberry Pi, the mount shows as
  /dev/ttyUSB0 or /dev/ttyACM0; if it's listed but won't open, add yourself to
  the "dialout" group (sudo usermod -aG dialout $USER) and log out and back in.
  To identify the right port, unplug the mount, note which entries disappear,
  plug it back in, and pick the one that returns.

Connect button won't turn green
  Make sure no other program (another dashboard window, a planetarium app,
  Arduino IDE) has the port open - only one program can use a serial port at a
  time. Confirm the mount is powered on and you selected the correct port.

The log shows "busy p..."
  That's the WiFi module saying "I'm still working on the last command." The
  dashboard already paces itself for this and reads replies patiently. If you
  still see it occasionally on an ESP32 (which answers more slowly than an
  ESP8266), simply run the action again - it's harmless. Persistent "busy"
  usually means the wrong WiFi module type is selected.

"Could not read WiFi address"
  Confirm the WiFi module selection matches your hardware, that you're on a
  serial connection, and that the mount has actually joined a network. Try Get
  WiFi Address again; the mount may have been mid-reply the first time.

"Did not see WIFI GOT IP" after Configure
  Double-check the SSID and password (the password field is case-sensitive).
  Make sure the network is in range and is a 2.4 GHz network - many of these
  modules don't support 5 GHz. Then try again.

RN131 shows "AUTH-ERR" or won't join, and keeps retrying
  The RN131 reached your network but was refused at login. Two common causes:
    - Wrong password. On an RN131 the module gets stuck retrying a failed
      login, which also blocks the app from re-entering command mode. Click
      Restore to Default first (this returns it to its own access point and
      stops the retrying), then Configure for Home Network again with the
      correct password.
    - A network the RN131 can't use. RN131 modules are 2.4 GHz WPA/WPA2 only.
      They cannot join a WPA3-only network, a WPA2/WPA3 "transition" network, or
      one that requires Protected Management Frames (PMF) - increasingly common
      on modern WiFi 6 routers. If the password is definitely right and it still
      fails, join a 2.4 GHz WPA2 network instead (a guest or IoT SSID is ideal).
  Spaces in the password are handled correctly now; an older version could
  truncate them and cause the same AUTH-ERR, so update if you haven't.

The mount seems "stuck" after a WiFi step
  The app always sends the exit command (###) to leave the mount's pass-through
  mode, even if an error happened - so this is rare. If it persists,
  power-cycle the mount and reconnect.

PyQt6 or pyserial "not found" at startup
  Install them with the command shown in the console message
  (pip install PyQt6 pyserial), then start the app again.

8. GLOSSARY
==============================================================================

  PMC-Eight           The Explore Scientific mount controller this app
                      configures.
  WiFi module         The wireless chip inside the mount - an ESP32, ESP8266,
                      or RN131. Different modules speak slightly different
                      command languages, which is why you select the type.
  Serial / COM port   The connection over the USB cable. Shows as COMx on
                      Windows or /dev/tty... on macOS/Linux.
  SSID                The name (Service Set Identifier) of a WiFi network.
  IP address          The mount's numeric Internet Protocol address on your
                      network, e.g. 192.168.1.50. You need it to connect over
                      WiFi.
  Access point (AP)   When the mount makes its OWN WiFi network instead of
   mode               joining yours. "Restore to Default" returns an RN131 to
                      this mode.
  Pass-through mode   A temporary state where the mount relays your commands
                      straight to the WiFi module. The app enters and exits it
                      for you.
  Firmware            The software that runs inside the controller itself,
                      which you can update from the Firmware screen.
