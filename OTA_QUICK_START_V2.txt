================================================================================
  PMC8 ESP32 Over-the-Air (OTA) Firmware Update — User Guide (V2)
================================================================================

This guide is for ota_update_v2.py — the V2 update script, tool v2.4.

(The script prints its tool version in the banner when it starts. If you ask
for help with a problem, include that line — it tells us exactly which build
you are running.)

This guide explains how to update the ESP32 firmware on your PMC8 telescope
mount controller over WiFi, without opening the case or using any special
hardware. All you need is a computer, a USB cable, and Python.

Works on Windows, macOS, and Linux (including Raspberry Pi). Where the
commands differ, both are shown.

The V2 script supports two ways to connect:

  DIRECT mode:  Your PC connects to the PMC8's own WiFi network.
                No home WiFi needed. Simplest method.

  LAN mode:     Your PC and the PMC8 both connect to your home WiFi.
                Needed if DIRECT mode is not available.

The script automatically detects which mode to use.


WHAT YOU NEED
-------------
- PMC8 mount controller (firmware 20A02.x or later) with an ESP32 WiFi module

  *** IMPORTANT: this package updates ESP32 modules ONLY. ***
  Some PMC8 mounts have an ESP8266 module instead, which needs a different
  firmware package. You do not have to work out which you have — the script
  checks, and stops safely before changing anything if the firmware does not
  match your mount.

- Windows, macOS, or Linux (including Raspberry Pi)
- USB cable connecting the computer to the PMC8
- Python 3 installed (see "Installing Python" below)
- The following files (provided together):
    ota_update_v2.py    — the update script
    (firmware .bin)     — the new firmware (you will be asked for the filename)

For LAN mode only:
- A home WiFi network (2.4GHz — the ESP32 does not support 5GHz)
- The PC must be on the same WiFi network the PMC8 will connect to


INSTALLING PYTHON
-----------------
The script requires Python 3. If you already have it, skip ahead.

On macOS: Python 3 is already installed. To check, open Terminal and run:
  python3 --version
If it is missing, macOS will offer to install the developer tools — accept.

On Linux / Raspberry Pi: Python 3 is already installed on virtually every
distribution. Check with:
  python3 --version

On Windows, use one of the two options below.

Option A — Microsoft Store (easiest):
  1. Open the Microsoft Store (Start menu -> "Microsoft Store")
  2. Search for "Python 3"
  3. Click "Get" or "Install" on the latest Python 3.x
  4. Done — Python is automatically added to PATH

Option B — python.org:
  1. Go to https://www.python.org/downloads/
  2. Download the latest Python 3 installer for Windows
  3. Run the installer
     *** IMPORTANT: CHECK THE BOX "Add python.exe to PATH" ***
     Then click "Install Now"
  4. Close and reopen your Command Prompt / PowerShell

To verify Python is installed, open a Command Prompt and run:
  python --version

You should see "Python 3.x.x".

NOTE: The script will automatically install any other required packages
(pyserial) — you do not need to install them yourself.


BEFORE YOU BEGIN
----------------
- The PMC8 must be powered on and fully booted (wait ~15 seconds after
  power-on before starting)
- Close any other programs that might be using the serial port (ExploreStars,
  the ExploreStars PWA server, SkySafari, terminal programs, etc.)
- For DIRECT mode: connect your PC to the PMC8's WiFi network and
  make sure no other devices are connected to it
- For LAN mode: know your WiFi network name (SSID) and password


THE SERIAL PORT — USUALLY AUTOMATIC
------------------------------------
You do NOT need to find or type the serial port. Connect the USB cable, and
the script finds the mount by itself:

  PMC-Eight found on COM3  (USB Serial Port [AK06KTGQ])

If more than one USB-serial adapter is plugged in, the script cannot tell
which is the mount, so it lists them and asks you to pick a number. The
easiest fix is to unplug the other adapters and run it again.

If it finds nothing at all:
  - Check the USB cable is connected at both ends
  - Check the PMC8 is powered on
  - You may need the driver for your USB-serial adapter (FTDI, CH340, or
    CP210x — check the adapter's label)

Naming the port yourself (rarely needed):
  Windows           python  ota_update_v2.py --port COM3
  macOS             python3 ota_update_v2.py --port /dev/cu.usbserial-XXXX
  Linux / Pi        python3 ota_update_v2.py --port /dev/ttyUSB0

  To list ports yourself:
    Windows     Device Manager -> Ports (COM & LPT)
    macOS       ls /dev/cu.*        (use the cu.* name, NOT its tty.* twin)
    Linux / Pi  ls /dev/ttyUSB* /dev/ttyACM*


PREPARE THE UPDATE FILES
-------------------------
Place the script and firmware file in the same folder. For example:

  Windows           C:\PMC8_Update\
  macOS / Linux     ~/pmc8-ota/

      ota_update_v2.py
      start_ota.sh              (Linux / Raspberry Pi launcher)
      start_ota.command   (macOS launcher — double-click this)
      esp-at.bin                (or whatever the firmware file is named)

Keep the files together in one folder. The launcher looks for the updater
beside itself and will tell you if they have been separated.


LAUNCHERS — THE EASY WAY (no typing)
-------------------------------------
The zip contains two launchers. They do the same thing; the only difference is
how your system starts them.

  macOS              double-click   start_ota.command
  Linux / Pi         run            ./start_ota.sh

Either one checks what it needs, finds your mount and runs the updater. You
never type a command or a serial-port name.

(`start_ota.sh` does the work. `start_ota.command` is a small wrapper that runs
it — the `.command` name exists because that is what the macOS Finder needs in
order to double-click a script. Linux ignores the extension entirely and goes by
the file's executable bit, so on a Pi desktop double-clicking EITHER file
generally works too, depending on how your file manager is set up. Running
`./start_ota.sh` from a terminal is the one that always works.)

On Linux / Raspberry Pi:

    chmod +x start_ota.sh      # only if your unzip tool dropped the permission
    ./start_ota.sh

The launcher warns you if your user is not in the `dialout` group, which Linux
needs in order to open the USB serial port. To fix it:

    sudo usermod -aG dialout $USER

then REBOOT. Logging out and back in is NOT enough on current Ubuntu/GNOME --
the systemd user session survives a logout and keeps your old group membership,
so the port still refuses to open and it looks like the tool is broken. If you
want it in the current terminal without rebooting, run:  newgrp dialout

*** FIRST TIME ONLY — macOS will refuse to open it once ***

  This is normal and expected. The launcher is not signed by a paid Apple
  developer account, so the first time you double-click it macOS says something
  like "cannot be opened because it is from an unidentified developer" or
  "Apple could not verify it is free of malware."

  It takes about fifteen seconds to allow it:

      1. Double-click start_ota.command.
         macOS refuses. Click  Done  (or OK) to dismiss the message.

      2. Open  System Settings  ▸  Privacy & Security

      3. Scroll down to the Security section. You will see a line saying
         "start_ota.command was blocked."
         Click  Open Anyway.

      4. Confirm with your password / Touch ID if asked.

      5. Double-click start_ota.command again. Click  Open.

  It runs, and from then on double-clicking just works. You only do this once.

  (Verified on macOS 2026-08-01 — this is exactly the path a real first run
  takes.)

  IF INSTEAD IT SAYS "Permission denied":
      That is a different problem — your unzip tool stripped the file's
      permissions. Open Terminal (Applications ▸ Utilities ▸ Terminal), type
      the letters  s  h  and a SPACE:

          sh

      then drag start_ota.command from Finder into the Terminal window
      and press Return. That runs it regardless, and repairs the permissions so
      later double-clicks work.

If you would rather not use the launcher at all, the manual commands are below
and work fine.


GETTING HELP
-------------
To see all available command-line options, run:

  Windows           python  ota_update_v2.py --help
  macOS / Linux     python3 ota_update_v2.py --help

To check which version of the tool you have:

  Windows           python  ota_update_v2.py --version
  macOS / Linux     python3 ota_update_v2.py --version


RUN THE UPDATE — DIRECT MODE
------------------------------
Use this method when your PC is connected to the PMC8's WiFi network.

1. Connect your PC's WiFi to the PMC8 network (usually "PMC8_XXXX")
2. Disconnect any other devices from the PMC8 WiFi
3. Make sure the PMC8 is powered on and fully booted
4. Close any programs using the serial port
5. Open a terminal and navigate to your folder:

     Windows        Command Prompt or PowerShell:   cd C:\PMC8_Update
     macOS / Linux  Terminal:                       cd ~/pmc8-ota

6. Run the script. It finds the serial port on its own:

     Windows           python  ota_update_v2.py
     macOS             double-click start_ota.command
     Linux / Pi        ./start_ota.sh

   It will ask for the firmware filename (press Enter for the default).

   The script will auto-detect DIRECT mode (your PC is on 192.168.47.x).

7. The script shows the installed and new firmware versions, then asks
   if you want to proceed.

8. Wait for the update to complete (typically 2-4 minutes).

9. Done! The PMC8 is already back in AP mode — ready to use.


RUN THE UPDATE — LAN MODE
---------------------------
Use this method when your PC is on a home WiFi network.

1. Make sure the PMC8 is powered on and fully booted
2. Close any programs using the serial port
3. Open a terminal and navigate to your folder:

     Windows        Command Prompt or PowerShell:   cd C:\PMC8_Update
     macOS / Linux  Terminal:                       cd ~/pmc8-ota

4. Run the script:

     Windows           python  ota_update_v2.py
     macOS             double-click start_ota.command
     Linux / Pi        ./start_ota.sh

   The script finds the serial port itself, then prompts you for:
     - WiFi SSID (your home network name — case-sensitive!)
     - WiFi password (case-sensitive!)
     - Firmware filename (press Enter for default: esp-at.bin)

   Or provide everything on the command line (Windows shown):

     python ota_update_v2.py --ssid "YourWiFiName" --password "YourWiFiPassword" --firmware esp-at.bin

5. The script shows the installed and new firmware versions, then asks
   if you want to proceed.

6. Wait for the update to complete (typically 2-4 minutes).

7. Done! Power cycle the PMC8 to return to normal operation.

TWO PAUSES THAT LOOK LIKE THE SCRIPT HAS FROZEN — BOTH ARE NORMAL:

  1. "Checking the mount is responding..."
     On macOS and Linux, opening the serial port makes the mount restart.
     The script waits for it (about 25 seconds) and shows a countdown. On
     Windows this is instant and you will not see the countdown at all.

  2. "Waiting 15s for the ESP32 modem to reset"
     The script turns off Envision mode first, because the ESP32 will not
     accept the update commands while it is on. The WiFi module restarts;
     the mount itself does not.

Envision mode is left OFF after the update. Turn it back on in ExploreStars
Envision: Setup -> Envision Mode. The script reminds you of this at the end.


TROUBLESHOOTING
---------------

"STOP - WRONG FIRMWARE FOR THIS MOUNT" (Phase 2):
  - Your mount has an ESP8266 WiFi module; this package is for ESP32 modules.
    They are different chips, not different versions.
  - Nothing has been changed on your mount. It is safe.
  - You need the ESP8266 firmware package instead — ask where to get it.

"Could not open <port>" (Phase 1):
  - Is another program using the serial port? ExploreStars, the ExploreStars
    PWA server, SkySafari and terminal programs all hold it open. Close them
    and try again.
  - On macOS, make sure you are using a /dev/cu.* name, not /dev/tty.*

"No response from the mount after 45 seconds" (Phase 1):
  - Is the PMC8 powered on?
  - If more than one USB-serial adapter is plugged in, the script may have
    picked the wrong one. Unplug the others and try again.

"ESP32 not responding to AT commands" (Phase 2):
  - Is the PMC8 fully booted? Wait at least 15 seconds after power-on.
  - Power cycle the PMC8 and try again.
  - (Envision mode also causes this, but the script now turns it off for you
    automatically, so this should no longer happen.)

"PC is on PMC8 subnet but not at expected 192.168.47.11" (Phase 1):
  - Other devices are connected to the PMC8 WiFi.
  - Disconnect all other devices, then disconnect and reconnect your PC.

"Failed to join WiFi" (Phase 3, LAN mode only):
  - Is the SSID exactly correct? WiFi names are case-sensitive.
    Example: "NETGEAR85" is NOT the same as "netgear85"
  - Is the password correct?
  - Is the WiFi network 2.4GHz? The ESP32 cannot connect to 5GHz networks.
  - Is the PMC8 within range of the WiFi router/access point?

"OTA NOT POSSIBLE - USE THE SERIAL FLASH TOOL" (Phase 5):
  - Your ESP32's firmware is too old to support over-the-air updates (it does
    not have the AT+USEROTA command). Nothing on your mount has been changed.
  - Get the SERIAL FLASH tool instead — it uses the same USB cable and writes
    the firmware directly:
        https://github.com/wesmcd6/pmc8-tools/tree/esp32-serial-flash
    Once it has landed current firmware, this OTA updater works from then on.
  - The firewall may be blocking the connection. Try running the Command
    Prompt as Administrator (right-click -> "Run as administrator").
  - Check that no other program is using port 8000.

"Could not start HTTP server on port 8000" (Phase 4):
  - Another program is using port 8000. Close it and try again.

OTA transfer starts but never completes:
  - Check that the PC and PMC8 can reach each other on the network
  - Try running as Administrator for firewall access
  - Make sure the WiFi signal is strong

"PC has not reconnected to the PMC8 WiFi" (after reboot, DIRECT mode):
  - The PMC8 rebooted and your PC lost the WiFi connection.
  - Reconnect your PC to the PMC8 WiFi and press Enter.
  - If it still fails, the update may still have succeeded — the script
    will check the firmware version via serial and let you confirm.

"Firmware file is too large for OTA" (Phase 1):
  - You selected the full factory image (factory_WROOM-32.bin) instead of
    the OTA binary (esp-at.bin). The OTA binary is under 2MB. The factory
    image is a full 4MB flash and must be loaded via serial:
        https://github.com/wesmcd6/pmc8-tools/tree/esp32-serial-flash

"python is not recognized" (Windows):
  - Python is not installed or not on PATH. See "Installing Python" above.

"command not found: python" (macOS / Linux):
  - Use python3, not python. On macOS and Linux the command is python3.

macOS asks "Do you want the application Python to accept incoming network
connections?":
  - Click Allow. The ESP32 has to reach the update server running on your Mac.

If all else fails:
  - Power cycle the PMC8 — the previous firmware is still intact.
  - The OTA process is safe: if it fails, the PMC8 keeps its existing
    firmware. You can always try again.


COMMAND-LINE OPTIONS
---------------------
Run the script with --help to see all options.

  --port PORT       Serial port. NOT normally needed — the script finds the
                    mount by itself. Only use this to override the choice.
                      Windows      COM3
                      macOS        /dev/cu.usbserial-XXXX
                      Linux / Pi   /dev/ttyUSB0
  --ssid SSID       WiFi network name (LAN mode only)
  --password PASS   WiFi password (LAN mode only)
  --firmware FILE   Firmware filename (default: esp-at.bin)
  --version         Print the tool version and exit

Options can be given in any order. If you omit any, the script will
prompt you to enter them.


SAFETY NOTE
-----------
The OTA update is safe. If the transfer fails or is interrupted:
  - The PMC8 keeps its existing working firmware
  - Just power cycle and try again
